# QQ 宠物接口助手（Private Preview）

一个正在验证中的电脑端 QQ 宠物自动控制工具。项目复用已登录电脑版 QQ/NapCat 的会话、签名和加密封包，通过本机 OneBot `send_packet` 调用宠物 OIDB 接口，不需要长期连接手机或 ADB。

> 当前仓库用于展示阶段性成果，仍处于私有预览阶段。请只操作自己的 QQ 账号，并自行承担非公开接口发生变化的风险。

| --- | --- | --- |
| 状态读取 | 可用 | 金币、心情、体力、清洁、综合值 |
| 食物与洗护库存 | 可用 | 饼干、虾仁、香皂片、沐浴球 |

本地协议、客户端解析和调度测试目前为 **18/18 通过**。

## 调度逻辑

- 体力或清洁低于默认阈值 80 时，优先照顾宠物；库存不足可自动用金币补货。
- 配置时间后优先尝试冒险。
- 金币充足时优先学习，否则尝试打工。
- 学习、打工、冒险启动前读取服务器行为规则；没有可执行路径时安全跳过，不发送固定封包。
- 任务完成后按 `storyId` 结算并持久化，避免对旧任务反复结算。

## 当前限制

- 工作地点、岗位目录和收益字段尚未完整恢复，因此“最高收益岗位”目前只是配置偏好。
- 自动雇佣好友、访问好友和“踩踩”接口尚未完成。
- 被雇佣召回已有调度框架，但仍需要更多真实场景验证。
- `GetPageRules` 可能阶段性返回空路径；当前实现会跳过，不把接口成功误报为任务成功。
- 项目依赖 NapCat 提供的原始封包能力，尚不是独立 QQ 登录客户端。

## 快速开始

1. 准备已登录目标账号的电脑版 QQ 和 NapCat，并创建仅监听 `127.0.0.1` 的 OneBot HTTP 服务。
2. 复制 `config.example.yaml` 为 `config.yaml`，填写自己的 UIN、`pet_id`、端口和本机令牌。
3. 使用 Python 3.11+ 运行：

```powershell
py -3 main.py
```

也可以双击 `start-interface-copilot.bat`。

首次接入新账号时建议保留安全模式，确认状态读取正常后再开放写操作。

## 测试

```powershell
py -3 -m unittest discover -s tests -v
```

## 安全说明

- `config.yaml`、运行日志、抓包、APK、设备提取物和账号响应均被 `.gitignore` 排除。
- 不要把 OneBot 端口监听到公网，也不要提交真实 UIN、`pet_id` 或访问令牌。
- 仓库不包含 QQ、NapCat、APK 或其他第三方二进制文件。
